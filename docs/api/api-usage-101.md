# RAG Core API usage 101

This guide takes an application from an empty RAG Core instance to a working
search experience. It explains the vocabulary along the way and ends with a
small, reusable Swift client.

The examples use the local base URL:

```text
http://localhost:8000
```

The [OpenAPI contract](rag-core-openapi.yaml) is the authoritative reference
for every field and response. This guide is the practical companion to it.

## What this API does

RAG means **retrieval-augmented generation**. Before asking a language model to
answer a question, an application retrieves the most relevant passages from
its own material and supplies those passages as context.

RAG Core performs the retrieval half of that workflow:

1. Create a logical collection that describes the index.
2. Add documents as text plus typed metadata.
3. Ask a natural-language question.
4. Receive ranked, citable text chunks.
5. Optionally pass those chunks to a language model to compose an answer.

RAG Core deliberately does not generate the final answer. It also hides the
embedding service and vector database. A client sends text—not vectors—and
works only with stable product concepts such as collections, documents, and
retrieval results.

```text
Your app  →  RAG Core  →  private embedding and vector infrastructure
               │
               └── ranked text chunks returned to your app
```

## The four concepts to learn first

### Logical collection

A **collection** is a searchable body of related material, such as an employee
handbook, a product manual, or a support knowledge base. Its public
`collection_id` is logical and stable. Clients never need to know how or where
the vectors are physically stored.

Creating a collection also declares an immutable contract: embedding model,
vector dimension, distance metric, metadata fields, and index schema version.
Changing that contract later requires a new **generation** and a reindex.

### Document and chunk

A **document** is the unit your application owns and updates. You give it a
stable `document_id` and the complete text content.

RAG Core divides that content into overlapping **chunks**, embeds them, and
indexes them. Retrieval returns chunks because a focused passage is usually
more useful than an entire long document. Chunk IDs and the content-derived
`document_version` are generated by Core.

Sending the same `document_id` with changed content replaces its indexed
version; it does not append a second logical document. Sending identical
content with changed metadata updates the metadata on the same deterministic
chunks.

### Embedding

An **embedding** is a numeric representation of meaning. Similar passages and
queries receive nearby representations, which makes semantic search possible.
Application clients never create or send embeddings. They declare the
collection's compatibility contract once, then send ordinary text.

### Retrieval

A **retrieval** turns a natural-language query into a ranked list of chunks.
`top_k` means “return at most the best *k* matches.” A `minimum_score` removes
weak matches. The returned score is between 0 and 1, but it is a relevance
indicator—not a probability or a confidence percentage.

## Start the local stack

From the repository root:

```sh
cp .env.example .env
docker compose --profile application up --build --wait
curl --fail http://localhost:8000/health/ready
```

The first startup downloads the pinned embedding model and may take longer.
Use `/health/live` to ask only whether the Core process can answer. Use
`/health/ready` before sending application traffic; readiness also checks the
embedding service, vector store, and collection catalog.

## The complete first workflow

### 1. Create a collection

```sh
curl --fail-with-body \
  --request POST http://localhost:8000/v1/vector-collections \
  --header 'content-type: application/json' \
  --header 'Idempotency-Key: create-handbook-v1' \
  --data '{
    "collection_id": "employee-handbook",
    "embedding": {
      "model_id": "all-MiniLM-L6-v2",
      "revision": "c9745ed1d9f207416be6d2e6f8de32d1f16199bf",
      "dimension": 384,
      "normalized": true,
      "distance_metric": "cosine"
    },
    "index_schema_version": 1,
    "metadata_fields": [
      {"name": "department", "type": "keyword", "indexed": true},
      {"name": "language", "type": "keyword", "indexed": true},
      {"name": "year", "type": "integer", "indexed": true}
    ],
    "isolation_policy": "shared"
  }'
```

A new resource returns `201 Created`. The response contains a generated
`active_generation_id`; keep it if an operator UI will later manage collection
generations or retirement.

What the contract fields mean:

| Field | Meaning |
| --- | --- |
| `collection_id` | Stable public name. It must start with a lowercase letter and contain 3–63 lowercase letters, digits, or hyphens. |
| `model_id` | Embedding model identity expected by this collection. |
| `revision` | Exact, pinned model artifact revision. Pinning prevents a moving model from silently making old and new vectors incompatible. |
| `dimension` | Number of values in each private vector. The default model uses 384. |
| `normalized` | Whether vectors are scaled to unit length. This is part of compatibility. |
| `distance_metric` | How similarity is measured: `cosine`, `dot`, or `euclid`. Use the configured default unless you deliberately operate another compatible model. |
| `index_schema_version` | Your integer version for the chunk/index contract. Increase it when a changed indexing policy requires a new generation. |
| `metadata_fields` | Allowed typed fields on documents. Only fields with `indexed: true` can be used in retrieval filters. |
| `isolation_policy` | V1 supports `shared`; trusted tenant isolation is added by the server, not accepted from request metadata. |

Collection creation is not a “create if absent with any definition” operation.
If the logical ID already exists with another request, Core returns a conflict.
Inspect it with `GET /v1/vector-collections/{collection_id}` instead of guessing
that its contract is compatible.

### 2. Add a document

```sh
curl --fail-with-body \
  --request POST http://localhost:8000/v1/rag/documents \
  --header 'content-type: application/json' \
  --header 'Idempotency-Key: ingest-leave-policy-2026-v1' \
  --data '{
    "collection_id": "employee-handbook",
    "document_id": "leave-policy-2026",
    "content": "Parental leave is available for sixteen weeks. Requests are submitted to People Operations.",
    "metadata": {
      "department": "people",
      "language": "en",
      "year": 2026
    }
  }'
```

This is a synchronous product operation. Before returning, Core validates the
document, normalizes and chunks it, creates embeddings in bounded batches,
checks collection compatibility, indexes the new version, and removes older
versions of the same document.

The response reports `chunks_indexed` and a `document_version` such as
`sha256:…`. The version is calculated from normalized content. It is useful for
citations and cache validation, but the application should continue to address
the document by its own stable `document_id`.

Metadata values must match the collection declaration:

- `keyword` → JSON string
- `integer` → JSON integer
- `float` → finite JSON number
- `boolean` → JSON `true` or `false`

Undeclared fields, wrong types, arrays, objects, and reserved security fields
are rejected. Metadata is descriptive and filterable; it is not an access
control channel.

### What is an idempotency key?

An operation is **idempotent** when repeating it has the same intended result
as performing it once. Mobile networks fail in awkward places: the server may
finish indexing while the app loses the response. A retry must not create
duplicate work or accidentally bind a different document to the old attempt.

`Idempotency-Key` is an opaque client-generated token for one logical request.
For example, use a UUID, a durable upload-job ID, or
`ingest-<document>-<local revision>`. It must contain 8–128 printable ASCII
characters.

The rules are important:

1. Create the key before the first attempt.
2. Persist and reuse that exact key and exact body for retries.
3. Generate a new key when the intended request changes.
4. Never reuse one key for unrelated documents.

A completed retry returns the stored body with `200 OK` and
`Idempotency-Replayed: true`. Reusing the same key with a different body returns
`409` and `idempotency_conflict`—a useful signal that the client has a bug.

In this boilerplate the idempotency store lives in one Core process and is
cleared on restart. Production should replace it with a shared, durable,
TTL-enforcing store before adding replicas. Deterministic document/chunk IDs
still make same-content ingestion retry-safe, but only a durable idempotency
store can replay the exact earlier response across processes and restarts.

### 3. Retrieve relevant information

```sh
curl --fail-with-body \
  --request POST http://localhost:8000/v1/rag/retrievals \
  --header 'content-type: application/json' \
  --data '{
    "collection_id": "employee-handbook",
    "query": "How long is parental leave?",
    "top_k": 5,
    "minimum_score": 0.65,
    "filter": {
      "all": [
        {"field": "department", "operator": "eq", "value": "people"},
        {"field": "year", "operator": "gte", "value": 2025}
      ]
    }
  }'
```

A successful no-match is `200 OK` with `results: []`. Do not turn an empty
array into a transport error. It usually means the threshold is too strict,
the filter excludes the relevant material, or the collection does not contain
an answer.

Each hit includes:

- `rank`: one-based position in this response;
- `chunk_id`: stable citation identity for this indexed version;
- `document_id` and `document_version`: the source document identity;
- `text`: the passage to display or give to a language model;
- `score`: normalized relevance in `[0, 1]`, rounded to six decimals;
- `metadata`: the safe metadata stored during ingestion.

Scores are comparable for results produced by the same collection contract.
They are not calibrated probabilities and should not be compared across
different collections or embedding models. Tune `minimum_score` using a
representative evaluation set rather than assuming that `0.8` means “80%
correct.”

### Filter grammar

Filters are provider-neutral JSON expressions. The available predicates are:

| Operator | Valid use |
| --- | --- |
| `eq` | Exact equality for any declared metadata type |
| `in` | Membership in 1–20 values of the same type |
| `gt`, `gte`, `lt`, `lte` | Ordering for `integer` and `float` fields only |

Combine expressions with `all` (logical AND), `any` (logical OR), and `not`:

```json
{
  "all": [
    {"field": "language", "operator": "in", "value": ["en", "pt"]},
    {
      "not": {
        "field": "year",
        "operator": "lt",
        "value": 2025
      }
    }
  ]
}
```

Only fields declared with `indexed: true` may be filtered. A filter may contain
at most 10 predicates and nest at most 3 levels. The server also ANDs trusted
tenant/access rules into every search; a client cannot weaken those rules.

### 4. Replace a document

Send `POST /v1/rag/documents` again with the same `collection_id` and
`document_id`, the complete new content, and a **new** idempotency key. Indexing
is replacement, not append. Core writes the new deterministic version before
removing older chunks so a partial cleanup can be repaired by replaying the
request.

Do not send patches or only the changed paragraph. The request represents the
complete current document.

### 5. Delete a document from the index

```sh
curl --fail-with-body \
  --request DELETE \
  'http://localhost:8000/v1/rag/documents/leave-policy-2026?collection_id=employee-handbook'
```

Deletion removes every indexed chunk and version for this document in the
active collection generation. It does not delete the authoritative source in
your CMS, database, bundle, or file store.

Deletion is inherently idempotent. Deleting an already absent document returns
`200 OK` with `chunks_deleted: 0`, so clients can safely retry it without an
idempotency key.

## A reusable Swift client

The following code uses only Foundation and modern Swift concurrency. It is
suitable as a starting point for an iOS, iPadOS, or macOS app. In an iOS
Simulator, `localhost` refers to the Mac and works for a locally running Core
service. A physical iPhone needs a reachable HTTPS host (or deliberate local
network development configuration).

### JSON values, errors, and transport

RAG metadata is typed but heterogeneous, so the client needs a small JSON value
type. Arrays are included because the filter `in` operator accepts them;
document metadata itself must remain scalar.

```swift
import Foundation

enum JSONValue: Codable, Sendable, Equatable {
    case string(String)
    case integer(Int)
    case number(Double)
    case bool(Bool)
    case array([JSONValue])

    init(from decoder: Decoder) throws {
        let value = try decoder.singleValueContainer()
        if let bool = try? value.decode(Bool.self) { self = .bool(bool) }
        else if let int = try? value.decode(Int.self) { self = .integer(int) }
        else if let double = try? value.decode(Double.self) { self = .number(double) }
        else if let string = try? value.decode(String.self) { self = .string(string) }
        else if let array = try? value.decode([JSONValue].self) { self = .array(array) }
        else {
            throw DecodingError.typeMismatch(
                JSONValue.self,
                .init(codingPath: decoder.codingPath,
                      debugDescription: "Unsupported JSON value")
            )
        }
    }

    func encode(to encoder: Encoder) throws {
        var value = encoder.singleValueContainer()
        switch self {
        case .string(let item): try value.encode(item)
        case .integer(let item): try value.encode(item)
        case .number(let item): try value.encode(item)
        case .bool(let item): try value.encode(item)
        case .array(let items): try value.encode(items)
        }
    }
}

struct RAGAPIError: Decodable, Error, Sendable {
    let code: String
    let message: String
    let traceId: String
}

struct RAGHTTPError: Error, Sendable {
    let statusCode: Int
    let apiError: RAGAPIError?
    let traceId: String?
    let retryAfter: TimeInterval?
}

struct RAGResponse<Value: Sendable>: Sendable {
    let value: Value
    let traceId: String?
    let idempotencyReplayed: Bool
}

actor RAGClient {
    private let baseURL: URL
    private let session: URLSession
    private let encoder: JSONEncoder
    private let decoder: JSONDecoder

    init(baseURL: URL, session: URLSession = .shared) {
        self.baseURL = baseURL
        self.session = session

        let encoder = JSONEncoder()
        encoder.keyEncodingStrategy = .convertToSnakeCase
        self.encoder = encoder

        let decoder = JSONDecoder()
        decoder.keyDecodingStrategy = .convertFromSnakeCase
        self.decoder = decoder
    }

    private func encoded<Body: Encodable>(_ body: Body) throws -> Data {
        try encoder.encode(body)
    }

    private func send<Value: Decodable & Sendable>(
        method: String,
        path: String,
        queryItems: [URLQueryItem] = [],
        headers: [String: String] = [:],
        body: Data? = nil,
        as type: Value.Type = Value.self
    ) async throws -> RAGResponse<Value> {
        guard var components = URLComponents(
            url: baseURL.appendingPathComponent(path),
            resolvingAgainstBaseURL: false
        ) else { throw URLError(.badURL) }
        if !queryItems.isEmpty { components.queryItems = queryItems }
        guard let url = components.url else { throw URLError(.badURL) }

        var request = URLRequest(url: url)
        request.httpMethod = method
        request.setValue("application/json", forHTTPHeaderField: "Accept")
        request.setValue("10000", forHTTPHeaderField: "x-request-timeout-ms")
        if body != nil {
            request.setValue("application/json", forHTTPHeaderField: "Content-Type")
        }
        headers.forEach { request.setValue($1, forHTTPHeaderField: $0) }
        request.httpBody = body

        let (data, response) = try await session.data(for: request)
        guard let http = response as? HTTPURLResponse else {
            throw URLError(.badServerResponse)
        }

        let traceId = http.value(forHTTPHeaderField: "x-trace-id")
        guard (200..<300).contains(http.statusCode) else {
            let apiError = try? decoder.decode(RAGAPIError.self, from: data)
            let retryAfter = http.value(forHTTPHeaderField: "Retry-After")
                .flatMap(TimeInterval.init)
            throw RAGHTTPError(
                statusCode: http.statusCode,
                apiError: apiError,
                traceId: traceId,
                retryAfter: retryAfter
            )
        }

        return RAGResponse(
            value: try decoder.decode(Value.self, from: data),
            traceId: traceId,
            idempotencyReplayed:
                http.value(forHTTPHeaderField: "Idempotency-Replayed") == "true"
        )
    }
}
```

Keep the returned `traceId` in diagnostics. It lets an operator correlate the
app-visible failure with Core, embedding, and vector-store telemetry without
logging document or query content.

### Collection models and creation

```swift
enum DistanceMetric: String, Codable, Sendable { case cosine, dot, euclid }
enum MetadataType: String, Codable, Sendable { case keyword, integer, float, boolean }

struct EmbeddingContract: Codable, Sendable {
    let modelId: String
    let revision: String
    let dimension: Int
    let normalized: Bool
    let distanceMetric: DistanceMetric
}

struct MetadataField: Codable, Sendable {
    let name: String
    let type: MetadataType
    let indexed: Bool
}

struct CreateCollectionRequest: Encodable, Sendable {
    let collectionId: String
    let embedding: EmbeddingContract
    let indexSchemaVersion: Int
    let metadataFields: [MetadataField]
    let isolationPolicy = "shared"
}

struct CollectionGeneration: Decodable, Sendable {
    let generationId: String
    let state: String
    let embedding: EmbeddingContract
    let indexSchemaVersion: Int
    let metadataFields: [MetadataField]
    let isolationPolicy: String
    let createdAt: String
    let activatedAt: String?
    let sourceGenerationId: String?
}

struct Collection: Decodable, Sendable {
    let collectionId: String
    let activeGenerationId: String?
    let retired: Bool
    let generations: [CollectionGeneration]
}

extension RAGClient {
    func createCollection(
        _ request: CreateCollectionRequest,
        idempotencyKey: String
    ) async throws -> RAGResponse<Collection> {
        try await send(
            method: "POST",
            path: "v1/vector-collections",
            headers: ["Idempotency-Key": idempotencyKey],
            body: encoded(request)
        )
    }
}
```

Use it like this:

```swift
let client = RAGClient(baseURL: URL(string: "http://localhost:8000")!)

let collection = try await client.createCollection(
    CreateCollectionRequest(
        collectionId: "employee-handbook",
        embedding: EmbeddingContract(
            modelId: "all-MiniLM-L6-v2",
            revision: "c9745ed1d9f207416be6d2e6f8de32d1f16199bf",
            dimension: 384,
            normalized: true,
            distanceMetric: .cosine
        ),
        indexSchemaVersion: 1,
        metadataFields: [
            .init(name: "department", type: .keyword, indexed: true),
            .init(name: "language", type: .keyword, indexed: true),
            .init(name: "year", type: .integer, indexed: true)
        ]
    ),
    idempotencyKey: "create-handbook-\(UUID().uuidString)"
)

print(collection.value.activeGenerationId ?? "No active generation")
```

In a real app, collection creation is usually an administrative/setup action,
not something every device performs at launch.

// Persist this key with the upload job and reuse it after a transport failure.
let uploadKey = "upload-leave-policy-\(UUID().uuidString)"

Path segments must be URL-encoded if your document IDs can contain reserved URL

### Retrieval models, filters, and search

```swift
enum FilterOperator: String, Encodable, Sendable {
    case eq, `in`, gt, gte, lt, lte
}

indirect enum Filter: Encodable, Sendable {
    case predicate(field: String, operator: FilterOperator, value: JSONValue)
    case all([Filter])
    case any([Filter])
    case not(Filter)

    private enum Keys: String, CodingKey { case field, `operator`, value, all, any, not }

    func encode(to encoder: Encoder) throws {
        var container = encoder.container(keyedBy: Keys.self)
        switch self {
        case let .predicate(field, operation, value):
            try container.encode(field, forKey: .field)
            try container.encode(operation, forKey: .operator)
            try container.encode(value, forKey: .value)
        case .all(let filters): try container.encode(filters, forKey: .all)
        case .any(let filters): try container.encode(filters, forKey: .any)
        case .not(let filter): try container.encode(filter, forKey: .not)
        }
    }
}

struct RetrievalRequest: Encodable, Sendable {
    let collectionId: String
    let query: String
    let topK: Int
    let minimumScore: Double
    let filter: Filter?
}

struct RetrievalHit: Decodable, Sendable, Identifiable {
    let rank: Int
    let chunkId: String
    let documentId: String
    let documentVersion: String
    let text: String
    let score: Double
    let metadata: [String: JSONValue]

    var id: String { chunkId }
}

struct RetrievalResponse: Decodable, Sendable {
    let collectionId: String
    let generationId: String
    let query: String
    let topK: Int
    let results: [RetrievalHit]
}

extension RAGClient {
    func retrieve(
        _ request: RetrievalRequest
    ) async throws -> RAGResponse<RetrievalResponse> {
        try await send(
            method: "POST",
            path: "v1/rag/retrievals",
            body: encoded(request)
        )
    }
}
```

```swift
let response = try await client.retrieve(
    RetrievalRequest(
        collectionId: "employee-handbook",
        query: "How long is parental leave?",
        topK: 5,
        minimumScore: 0.65,
        filter: .all([
            .predicate(field: "department", operator: .eq, value: .string("people")),
            .predicate(field: "year", operator: .gte, value: .integer(2025))
        ])
    )
)

if response.value.results.isEmpty {
    print("No sufficiently relevant passage was found.")
} else {
    for hit in response.value.results {
        print("[\(hit.rank)] \(hit.documentId) — \(hit.score): \(hit.text)")
    }
}
```

When building a generation prompt, treat retrieved text as untrusted data, keep
the `document_id`, `document_version`, and `chunk_id` beside every passage, and
render those identities as citations in the final answer. Do not let text from
a retrieved document override your application's system instructions.

## Timeouts, retries, and cancellation

Clients may send `x-request-timeout-ms` from 100 through 30,000. It is an
end-to-end budget: Core propagates the remaining time to dependencies rather
than giving each dependency a fresh full timeout. The default is 10 seconds.

Use a client-side timeout slightly longer than the Core budget so Core has time
to return its structured error. With Swift concurrency, cancelling the task
running `URLSession.data(for:)` cancels the request.

Retry policy should depend on both HTTP status and operation semantics:

| Result | Suggested behavior |
| --- | --- |
| Network interruption | Retry ingestion/create with the same body and idempotency key; deletion is also safe to retry. |
| `504` | Retry with capped exponential backoff if the user action is still relevant. Reuse the idempotency key. |
| `503` | Honor `Retry-After` when present, then back off with jitter. |
| `400`/`413`/`422` | Fix or reduce the request; retrying it unchanged will not help. |
| `404` | Check the logical collection/document/generation identity and lifecycle. |
| `409 idempotency_conflict` | Do not retry under that key. Investigate key reuse and create a new logical request. |
| `409 embedding_schema_mismatch` | Operational incompatibility; the collection/model contract needs attention. |
| `412 precondition_failed` | Re-read collection state before another lifecycle or destructive action. |
| `500` | Retry only when the operation is safe, with a strict attempt limit; report the trace ID. |

**Exponential backoff** means waiting progressively longer between attempts,
for example roughly 0.5 s, 1 s, 2 s, and 4 s. **Jitter** adds randomness so
many devices do not all retry at the same instant. Always cap both delay and
attempt count, and make cancellation stop the retry loop immediately.

## Error handling

All application errors use a stable envelope:

```json
{
  "code": "invalid_request",
  "message": "The request is invalid.",
  "trace_id": "8a31a31cd1464d659f93ac572bc54121",
  "details": {
    "fields": [
      {"path": "query", "reason": "must not be blank"}
    ]
  }
}
```

Branch on `code`, not the human-readable `message`. Messages may improve over
time, while codes are the programmatic contract. Show a useful user-facing
message, but retain `trace_id` in diagnostics and support reports.

Do not log request bodies in error reporting: documents, queries, and metadata
may be sensitive. The API's trace ID exists specifically to correlate behavior
without copying that content into logs.

## Inspecting and listing collections

Use these operations for administrative screens:

```text
GET /v1/vector-collections?limit=50&cursor=<opaque value>
GET /v1/vector-collections/{collection_id}
```

The list response contains `items` and an optional `next_cursor`. A cursor is
an **opaque pagination token**: send it back exactly as returned. Do not parse,
modify, persist indefinitely, or infer ordering state from it.

The inspection response includes all retained generations and the current
`active_generation_id`. A generation is one immutable physical realization of
the logical collection:

- `building`: provisioning is in progress;
- `ready`: compatible and provisioned, but not serving traffic;
- `active`: currently receives ingestion and retrieval;
- `retired`: no longer active, retained for rollback/cleanup policy;
- `failed`: provisioning did not complete.

## Advanced collection lifecycle

Most application clients should stop here. Generation management is an
operator workflow for changing embedding or index contracts safely.

`POST /v1/vector-collections/{collection_id}/generations` provisions an empty
compatible generation and leaves it `ready`. It does **not** copy or re-embed
documents. The public ingestion endpoint always writes to the active
generation, so an authorized out-of-band rebuild and validation workflow must
populate the target before activation.

After validating document counts, isolation, filters, latency, and retrieval
quality, activate it with:

```json
{
  "generation_id": "gen_01JX1M7WZ9G9VPHN4HM7FZAAK7",
  "expected_active_generation_id": "gen_01JX0X7V6K3Y1QMMX6P8G4R9Y2"
}
```

The expected ID is an **optimistic concurrency** safeguard. It means “perform
this change only if nobody has changed the active generation since I read it.”
A stale value returns `412 precondition_failed`; re-read state instead of
blindly overwriting newer work.

Retiring a collection stops ingestion and retrieval immediately:

```sh
curl --fail-with-body \
  --request DELETE http://localhost:8000/v1/vector-collections/employee-handbook \
  --header 'X-Confirm-Retirement: employee-handbook' \
  --header 'If-Match: gen_01JX0X7V6K3Y1QMMX6P8G4R9Y2'
```

Repeating the logical ID prevents accidental deletion of the wrong resource.
`If-Match` provides the same stale-state protection. Retirement removes
request-path access but does not immediately destroy physical data. The
response's `retained_until` is the earliest separately authorized platform
cleanup time.

Never activate a freshly provisioned empty generation in a data-bearing
environment. The current boilerplate also runs one Core replica because its
catalog transitions are not transactionally serialized across replicas.

## Limits worth designing for

| Input | Limit |
| --- | --- |
| Document content | 256 KiB encoded UTF-8, maximum 512 chunks |
| Document ID | 1–128 permitted characters |
| Metadata | 32 scalar fields; 16 KiB canonical JSON total |
| Metadata key/string value | 64 / 512 characters |
| Query | 8,192 characters and 16 KiB encoded UTF-8 |
| Retrieval | `top_k` 1–100; `minimum_score` 0–1 |
| Filters | Depth 3, 10 predicates, 20 values for `in` |
| Idempotency key | 8–128 printable ASCII characters |
| Caller timeout | 100–30,000 ms |
| Collection page | `limit` 1–100, default 50 |

Requests reject unknown JSON fields. Treat validation failures as useful
contract feedback rather than silently discarding data on the client.

## Production checklist

Before pointing a shipped app at this service:

- expose only RAG Core; keep the embedding API and vector database private;
- add authentication and derive tenant/access rules from trusted identity;
- use HTTPS and a secret manager for service credentials;
- replace process-local idempotency storage with shared durable storage;
- keep one Core replica until catalog transitions have distributed
  serialization or a transactional catalog;
- keep original documents in an authoritative source outside the vector index;
- define backup, restore, reindex, retention, and generation rollback workflows;
- evaluate retrieval quality on representative questions and tune chunking,
  filters, `top_k`, and `minimum_score` using evidence;
- collect trace IDs while excluding raw content, queries, vectors, secrets, and
  high-cardinality identifiers from routine telemetry.
